# StreamLaughs website

Next.js App Router + TypeScript + Tailwind, with bundled local fonts. Run `pnpm --filter web dev` from repo root. Public pages and the recorded, clearly labelled `/demo` require no credentials. See [env and exact Twitch redirect URLs](../../docs/deploy-part5.md), [manual acceptance](../../docs/manual-part5.md) and [fixed identity](../../docs/extension-identity.md).

Defaults are SITE_URL=https://streamlaughs.vercel.app, RELEASE_REPO_OWNER=uzerkayat2004-gif and RELEASE_REPO_NAME=streamlaughs; all remain env-configurable. Public name, tagline, wordmark and metadata derive from product.config.json. For local OAuth, explicitly use SITE_URL=http://localhost:3000. Vercel configuration, GitHub auto-deploy settings, Twitch authentication and the connected crowd/backend values are in [the production handoff](../../docs/vercel-production.md). The production build generates the direct website ZIP automatically; no GitHub release is needed. No analytics or remote fonts are used.

Twitch code/state exchange and encrypted HttpOnly cookie handling are server-only. The OAuth scope is empty: no email or resource scope is requested. After validating the token and looking up the Twitch user, the callback persists only user ID, channel login and display name. User access/refresh tokens are never put in the session. Owner pages/API validate that encrypted, expiring identity session and the exact channel login before signing a short-lived Worker read token. Existing token-bearing sessions need a fresh login. Revoking Twitch authorization does not invalidate an already issued website session; log out here too, or it expires within eight hours. Archive lookup uses a separate server-memory app access token. The dashboard live adapter is receive-only and preserves the server's three-contributor floor.

The viewer walkthrough at `/try` copies the browser-independent popup, dot and all six recap stories from the extension, with scoped styles and explicitly simulated data. It requests no mic or Worker access. `/demo` remains the separate streamer dashboard preview. Store install buttons appear only when `chromeStoreUrl` or `edgeStoreUrl` is filled in product.config.json. The SVG wordmark uses outlined Bricolage Grotesque letterforms from the bundled OFL font; the extension icons and package remain unchanged.

Deploy target: Vercel, Root Directory apps/web, with outside-root source access enabled. Config is in vercel.json; secrets remain in Vercel env, never NEXT_PUBLIC values. The connected production site is documented in the production handoff. Automated OAuth uses a separate localhost-only mock provider, which production ignores; real Twitch consent/VOD alignment remain manual.

The website browser suite starts its own Next dev server, mock Twitch provider and local Wrangler, and precompiles routes before reporting readiness. Ports 3000, 4191, 4192 and 8787 must be free. Use `pnpm test:e2e:web` after the site-test extension build described in the main README. Optional `WEB_TEST_DIAGNOSTICS=1` logs navigation paths and test clicks, with OAuth query values omitted. It never enables production mock authentication.

The production build packages one byte-identical Chrome/Edge ZIP for `/download`, plus a versioned copy and SHA-256 in the gitignored public/downloads folder. Set SITE_URL and WORKER_API_URL (or VITE_CROWD_API_URL) before a production build. See [download build, limits and browser verification](../../docs/website-downloads-part8.md).

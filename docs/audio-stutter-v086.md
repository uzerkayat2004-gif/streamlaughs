# v0.8.6 native-playback performance

The owner reported renewed stutter on v0.8.5 with only the ZIP copy enabled and tab capture off. No numeric hardware report arrived. The prior controlled soak is retained as a failed baseline: 98 ms offscreen long task, mean elapsed model work about 630 ms/s, and a speech-worker stall reaching 44.9 seconds. This does not retrospectively identify the owner's Bluetooth endpoint or prove which hardware effect they heard.

## Proven code issues and changes

- A new AudioEngine regression went red: its native-playback mic graph still wired worklet → zero-volume gain → speaker destination. Zero gain did not remove that connection. The analysis worklet now has zero outputs and no destination edge. Real fake-microphone ZIP checks verify that it still supplies 16 kHz frames. The lab separately reports speaker connections and live tab-capture tracks. Native sessions must report both zero.
- One worker/thread was already used for Whisper, so extra ONNX threads were not the cause. However, a valid slow speech job had no sustained-work governor, and another utterance could wait behind it. The new governor wraps encoder/decoder session calls, yields between them, reserves at most about 1.6 seconds of elapsed speech work per rolling ten seconds (leaving headroom for VAD/YAMNet), and backs off on supported Long Tasks. Timer stalls remain diagnostics: hidden-worker timer throttling is not labelled CPU trouble. MessageChannel yields avoid the timer clamping that stalled a valid short-word control in an earlier candidate. Kernel estimates are separate: an expensive encoder does not impose an encoder-sized delay on each cheap decoder token. A first attempt with a fixed sleep after every call missed the second bro control; it was rejected and replaced.
- New speech segments are dropped while a previous job is busy, instead of building a backlog. The near-voice/calibration gate runs before transcription. Whisper’s WASM encoder/decoder is warmed on generated silence before reporting ready, rather than charging cold kernel compilation to the first real reaction. A valid in-flight job is not killed by a bridge wall-clock timeout. Laugh processing stays in its separate worker and retains the 500 ms, latest-window cadence.
- Microphone selection resolves default/communications aliases to an available physical device ID after permission, retaining an explicitly selected input. No sample rate or channel count is forced. EC/NS/AGC remain off at capture; normalization and 16 kHz resampling remain local. Enumeration can hide IDs before the initial visible permission grant, so the first permission probe still needs the browser default when no concrete ID is available.

Separate same-input local probes found that leaving the known encoder input dimensions dynamic prevented effective ONNX graph optimization: the same bro control took 12,889.5 ms in the encoder before the fix and 1,254.8 ms after fixing batch=1, feature size=80 and the original sequence=3000. The recognized word and confidence were unchanged. That optimization alone still delayed a reaction under the work cap. The final export uses a 20-second encoder context: it retains the first 1,000 original positional vectors and updates shape annotations, with every other initializer and the decoder unchanged. Speech segments remain capped at 2.4 seconds. A four-second trial weakened confidence and was rejected; the 20-second bro control retained logprob −0.600 (threshold −0.9), with 734.5 ms encoder work. The pinned upstream SHA, deterministic standard-library transform and derived receipts are in tools/whisper_context.py and models/model-files.json. Decoder cache lengths remain dynamic. The probes are elapsed-work observations, not a matched OS CPU benchmark or retrospective proof of the owner's Bluetooth failure.

Whisper feature extraction originally performed FFT/mel work on the whole 30-second padded waveform. The compact extractor computes the active signal plus a zero boundary window, then pads the mathematically equivalent silent feature tail to the original model shape. Three parity controls compare the full and compact tensors within 0.00001. The front-end parity test compares equivalent features for the configured context; it does not change the audio or decoder rules. The separate encoder-context specialization is described above. Feature extraction is budgeted too. Rolling CPU status now sums actual per-call windows instead of assigning an entire completed job to one second; the earlier ten-minute run had no main-thread long tasks or video drops but failed that old 8.2-second rolling measure, and is not relabelled a pass.

The governor measures elapsed feature/model-call work with explicit pacing sleeps excluded, a conservative scheduling measure rather than OS CPU utilization. It cannot preempt a single synchronous WASM kernel, promise a three-second word latency on every CPU, force a Bluetooth profile or change Windows Communications settings. The five-minute report records the observed rolling work budget, supported offscreen/content Long Tasks, separately labelled worker stalls, native video drops and remaining model detections. Worker Long Tasks are explicitly unavailable where Chromium does not expose that API. Native HTML video has no public audio-underrun counter: unavailable is never reported as zero underruns.

## Reproduce the automated proof

Build production packages, extract the final website ZIP and set AUDIO_PROBE_BUILD to that folder. Run `pnpm test:accuracy`, then `STUTTER_SECONDS=300 pnpm test:stutter` using platform-appropriate environment syntax. These are focused production-ZIP fixture tools, not the full/e2e runner. They use Chromium's WAV fake microphone, a local Twitch-shaped video page and real extension start, worklet and workers. No model/frame injection or production fan traffic. The soak samples mic/model/overlay switches before its steady-state five-minute measurement; setup counters and those phases remain in its report.

See verification-v086.txt and verification-v086-stutter.txt for final measured results. The owner shortened the final stability requirement to five minutes to meet the submission deadline. The same extracted ZIP must pass all seven accuracy cases, including exact three-laugh episodes and bro twice/no way once.

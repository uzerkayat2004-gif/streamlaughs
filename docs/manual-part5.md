# Part 5 manual acceptance

Keep the [Part 3 hardware checks](manual-part3.md) and [Part 4 crowd checks](manual-part4.md). Automated results are in verification-part5.txt; real Twitch login, hosted providers, physical Edge/audio and the long soak remain manual. Do not save cookies, bearer headers, OAuth codes or personal audio in screenshots/traces.

1. **Fixed ID:** load Chrome build from two different folders and two profiles; confirm `fkocldgggcmhihelohiicoakcfomhepg`. Repeat with Edge. Check root Worker EXTENSION_ORIGINS uses that common origin. The public key ships, the private PEM does not. A Part 1–4 path-derived install changes ID once; confirm new mic consent and no promise of automatic recap migration. Keyed subsequent reloads retain that profile's records.
2. **Public pages:** on desktop and a narrow phone viewport, inspect Home, Install (Chrome/Edge tab, copy address, updating guide), Privacy and For streamers. Test keyboard focus, reduced motion and all links. The default download link points to the intended streamlaughs release repository; it becomes usable after publication. An explicitly empty RELEASE_REPO_NAME must show coming soon. Product name changes only through product.config.json; verify manifest, wordmarks and titles after rebuild.
3. **Public privacy:** with a clean profile, visit pages/demo: no app cookies or analytics requests. Fonts are local. Demo is visibly test data from recorded crowd-sim; no Twitch login or live socket is needed. No numbers are described as real human viewers.
4. **Real OAuth:** register the exact local/production redirects in deploy-part5.md yourself. Log in via Twitch; consent requests identity only, no email/resource scope. Confirm your exact channel dashboard. Verify one HttpOnly Lax encrypted cookie, Secure/__Host on HTTPS. Reject altered/replayed/expired callback state and expired/revoked sessions. Log out through the page; a cross-origin POST must fail. Invalid callback links must not log out an already authenticated session.
5. **Owner isolation:** use two Twitch accounts. A cannot open B's dashboard or JSON history, including manually typed URLs and changed channel casing. No Worker owner key, Twitch secret or access token appears in browser JS, HTML props, URLs or JSON history. Anonymous viewer tokens and the retired Part 4 read key cannot fetch timelines. Do not record real token values while checking this.
6. **Live:** open two extension profiles plus a third sharing client on the same channel (or clearly marked local/dev crowd-sim). Both viewer extension and owner dashboard show the same live counts/words. With only two sharing, show “a few here” and no numeric zeros. Dashboard sockets send zero application frames, including pings. Reconnect after network loss without an outgoing backlog. Share-off still immediately stops extension sends.
7. **Past streams:** contribute for several minutes, then refresh the owner page and switch to past streams. Inspect the smooth glowing wave, top words, inline peak count and up to three distinct moment cards, with test tags where applicable. Test seven-day/30-day selection; no below-floor minutes or viewer rows exist. Short sessions may have fewer than three moments. Activity-only groups are marked approximate.
8. **Actual VODs:** with archives enabled, compare moment links to Twitch GET/videos created_at + duration. Check offset boundaries, VOD started late and multiple archives. With VODs off/expired or lookup unavailable, retain time and omit the watch button. Older minute-only words must be labelled; new markers use the words captured at the moment. Check real player alignment manually; processing/VOD encoding may add delay.
9. **Version dot:** build with SITE_URL, serve a newer valid version.json, and trigger popup/background wake. Confirm one credential-free request per 24 hours, no install/channel query, and a small dot linking only to SITE_URL/install. Repeated popup opens and failures must not poll continuously. Rebuild with current version to verify no update is advertised. The OFFLINE_PREVIEW=true build has no version network traffic; normal builds default to the selected SITE_URL.
10. **Production controls:** after your deployment, verify exact CORS origins for fixed unpacked ID, site and any store IDs; reject unknown origins. Keep production test traffic off and mock OAuth ignored. Test the kill switch and retention/owner authorization. Use aggregate usage metrics, without payload/token logs, to validate Free quotas. No cloud deployment, live OAuth consent or actual store publication was performed during local implementation.

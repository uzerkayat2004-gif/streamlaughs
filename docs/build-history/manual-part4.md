Use two PCs or two independent browser profiles on the same Twitch channel. Viewer accounts are never sent to StreamLaughs. Build with your local/dev API URL and configure both exact extension origins. Two PCs require an HTTPS development endpoint; localhost belongs to each PC. Keep production demo traffic disabled.

1. **Watch-only:** switch Listen and Share off in both profiles, start the stream. No offscreen document/media indicator. Both show “a few here”, without zeros or words. Inspect the background socket: session POST/handshake and incoming packets, zero outgoing application messages/pings. Do not save bearer headers or a network trace.
2. **Independent inputs:** enable Listen through Start/Welcome. Confirm audible Twitch replay and real personal reactions. Leave Share off: local counters change, socket still sends nothing. Each PC's local data stays separate.
3. **Floor with real API demo:** in local/dev run `pnpm --filter crowd-sim start --channel CHANNEL --viewers 2 --origin chrome-extension://ALLOWED_ID --duration 120`. Both watchers remain few, exact incoming `{"state":"few"}`. Run another simulator with one viewer: both show live counts and bro/no way bubbles, labelled **test traffic**. Repeating a phrase from just one identity must never produce a bubble. Stop simulators: within six seconds (normally sooner on close) both return few, no counts/labels.
4. **Real sharing:** stop simulation. Enable Share in A: outgoing packets only every two seconds, numeric reactions/swears and ≤3 approved phrases; no timestamps, names, transcript or audio. Two sharing profiles still get only few. A third profile or one marked simulator establishes the floor. Real-only traffic says live; a simulator changes it to live · test traffic.
5. **Opt-out/pause:** disable Share while reactions occur. No sends after toggle completion; pending counts clear. Receiving continues. Pause also stops sends; resume starts fresh counts. Listening off closes capture while crowd receiving continues. Previously transmitted contributions cannot be recalled from completed aggregates.
6. **Lifecycle:** switching active tabs/windows preserves the session. Start another channel: old capture/socket stops and saves, new session gets a fresh ID. Closing/navigating the watched tab saves once. No old-channel bubbles appear. Stop closes socket and local audio.
7. **Recovery:** disconnect/reconnect the network. UI becomes offline on close or ≤35 seconds without valid packets, then reconnects with backoff/jitter and no buffered reaction burst. Restart the extension service worker: audio owner is adopted, crowd reconnects with a fresh RAM-only token; no token exists in chrome.storage/Dexie. Watch-only still sends nothing.
8. **Storage/auth:** keep ≥3 contributors for over a minute. With the independent operator secret and allowed Origin, GET `/v1/channels/CHANNEL/timeline?from=EPOCH_MS&to=EPOCH_MS`, range ≤24h. Only eligible minute aggregates/approved phrases/server-time markers/test flag exist. No operator secret means 403; viewer tokens cannot read. Never put the read secret in browser code. Automated tests cover expired-row alarm cleanup; no 30-day manual wait is needed.
9. **Control/abuse:** in dev set CROWD_ENABLED false and restart/redeploy. New sessions fail closed; old sockets close on a later event/alarm. Unknown origins, malformed channels, binary/oversized/extra-field packets and >1 message/s fail (also covered automatically). Restore config. Production rejects simulator tokens unless you explicitly allow them.
10. **Recap/Edge:** finish an eligible crowd session: you vs crowd distinguishes personal session totals from instantaneous crowd peaks and retains test labels. Finish an offline/few-only session: no crowd story. Repeat on Edge; check minimal live/few/offline text, dot tooltip, calm few animation and unchanged drag/fullscreen behavior.

The floor counts anonymous contributor sessions, not verified people. Do not describe simulator clients or browser profiles as independent human viewers. Fresh IDs avoid install tracking but cannot hide IP/timing from Cloudflare.

# StreamLaughs v0.8.7 fan ratings

Eligible local sessions must be explicitly marked live, not a VOD/clip, and last at least 600 seconds. Legacy sessions without a live marker are not guessed. The rating appears before the recap’s final/share slide; the stop sheet opens that same slide. Choose 1–10 and up to three fixed reason IDs. The settings toggle defaults on; sending is always an explicit button press. Turning it off hides the offer and blocks every rating request.

The stream key uses a normalized Twitch broadcast start time from page metadata when available, otherwise channel:UTC-date. The fallback deliberately groups that channel’s broadcasts on the same UTC date. No audio or detector code is changed.

POST /v1/ratings accepts only channel, streamKey, integer score and up to three distinct enum reason IDs. Authorization carries a random installation token generated locally. Allowed extension origins are the fixed ZIP, Chrome and Edge IDs. It is not a Twitch username or login. The server computes HMAC(HMAC_KEY, install-token + separator + streamKey); it never stores the raw token or IP. Short-lived HMAC rate keys are held in bounded memory only. Origin checks and anonymous tokens are abuse friction, not proof of a unique human or cryptographic viewing attestation; the extension enforces live/10-minute eligibility. Replay IDs and replay payload fields are rejected server-side.

To replace a contribution, the separate SQLite-backed Ratings Durable Object temporarily retains the dedupe hash, previous score/reason IDs, first-submission time and expiry. Replacements subtract that contribution before adding the new one, without incrementing fan count. Each contribution is editable for exactly 24 hours. Alarm/request cleanup deletes the complete replacement row at 48 hours. No per-fan history remains after that. New submissions close 24 hours after the stream’s first rating; later first submissions still get their own full 24-hour edit window. Closing new submissions prevents reuse after dedupe deletion. Only per-stream count/sum/histogram/reason totals remain, retaining the latest 30 stream keys chronologically.

GET /v1/channels/:channel/ratings requires the existing short-lived channel-bound owner token. The website authenticates Twitch ownership server-side; no owner key is shipped to the browser. Each under-five result contains only locked:true and needed. Unlocked results contain rounded average, histogram, reason percentages and a deterministic sentence. Negative reasons are mentioned only at 20% or more. Last-ten trend entries use the same floor. No free text is accepted.

Local history keeps the chosen score; updates across sessions/recaps with the same stream key do not create another rating. Deleting all local data clears ratings and the random install token. Anonymous aggregates already submitted cannot be individually removed after unlinking. Cloudflare necessarily handles network addresses to deliver traffic, but application request observability is disabled.

The Worker uses free-plan SQLite-backed Durable Objects and migration v2-fan-ratings. Existing signing secrets and origin allowlists remain in place. No new permissions, model assets or detection thresholds are introduced. Store versions remain independent of the new ZIP version; store packages are prepared without uploading to stores.
